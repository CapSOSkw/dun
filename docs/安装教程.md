# dun 安装教程

这份教程按顺序讲：准备 → 安装 → 导入客户端 → 日常管理 → 排错。第一次装照着从头做就行，以后遇到问题直接翻对应的章节。

参考了原作者 Joey 的博客：[dun：一条命令装好 Reality 偷自己、AnyTLS、CF WS 和 Hysteria2](https://joeyblog.net/dun-reality-anytls-cfws-hysteria2.html)。博客里有终端截图，可以对照看。本仓库在原版基础上加了 Argo 隧道（VLESS + XHTTP），安装命令也换成了本仓库的地址。

## 一、准备三样东西

### 1. 一台 VPS

- **登录方式**：要能用 root 登录。
- **系统**：带 systemd 的 Linux，比如 Debian、Ubuntu、CentOS、Alma、Rocky。
- **架构**：amd64 或 arm64。
- **内存**：1GB 足够。装 Argo 隧道会多跑 Xray 和 cloudflared 两个进程，512MB 的机器会比较紧。

### 2. 一个接入了 Cloudflare 的域名

域名还没接入 Cloudflare（下文简称 CF）的话，先做这一步：

1. 登录 CF 控制台，添加网站，输入你的域名，选免费套餐（Free）。
2. CF 会给你两个 NS 地址（形如 `xxx.ns.cloudflare.com`）。
3. 到你买域名的地方（域名注册商），把这个域名的 NS 改成 CF 给的两个。
4. 等 CF 后台显示这个域名的状态是「有效 / Active」。通常几分钟到几小时。

dun 只会列出状态是 Active 的域名。

### 3. CF 的登录邮箱和 Global API Key

新版 CF 后台这样找：

1. 点右上角头像，再点「设置」。
2. 左栏 User settings 下展开「API 凭据」，点「API 密钥」。
3. 找到 Global API Key 这一行，点右边的「查看」，复制下来。

安装时 dun 会问 CF 登录邮箱和这把 Key。

**这把 Key 权限很大**，能管你整个 CF 账号。dun 把它存在 VPS 的 `/etc/dun/cf.json`，只有 root 能读；续期证书、刷新优选地址都要用它，所以会一直留着，卸载时一起删掉。VPS 要是被人拿下，Key 也会跟着泄露。介意的话，单独注册一个 CF 账号，只放节点用的域名。

## 二、安装

### 1. 登录 VPS，执行安装命令

用 SSH 登录 VPS（root），执行：

```bash
bash <(curl -fsSL https://github.com/CapSOSkw/dun/releases/latest/download/install.sh)
```

它会下载 dun 和官方的 sing-box，然后打开菜单。以后再管理，输入 `dun` 就回到这个菜单。

下载的每个文件都会核对 SHA-256：dun 自己对照 Release 里的 `sha256sums.txt`；sing-box、Xray、cloudflared 对照 GitHub 给它们官方 Release 文件附的校验值。对不上就不装，并提示「校验失败」。

### 2. 选要装的协议

| 菜单 | 装什么 | 适合 |
|---|---|---|
| 1 | Reality 偷自己 | 直连，速度最好，首选 |
| 2 | AnyTLS | 直连，备用，换个协议换个特征 |
| 3 | CF WS（套 Cloudflare） | 保底，VPS 的 IP 被墙了也能用 |
| 4 | 1、2、3 一起装 | **第一次装推荐选这个** |
| 5 | Hysteria2 | 走 UDP，线路差、丢包多的机器用 |
| 6 | Argo 隧道（VLESS + XHTTP） | VPS 不开公网端口，IP 被墙也能用；NAT 机器、纯 IPv6 机器也能装 |

5 和 6 不在「一起装」里，需要的话装完 4 再单独选。

### 3. 安装过程中会问什么

大部分问题直接回车用默认值就行。会问到的有：

- **端口**：Reality、AnyTLS 默认用 443。443 被别的程序占着的话，dun 会提示并换成随机端口，不会去抢。
- **NAT 机器的外网端口**：dun 发现是 NAT 机器时，会多问一句外网端口，填服务商给你映射的端口。内外端口一样的（比如甲骨文），直接回车。
- **CF 邮箱和 Key**：只问一次，验证通过才往下走，填错了会让你重填。
- **用哪个域名**：从你 CF 账号里 Active 的域名中选一个。
- **子域名前缀**：回车让 dun 随机生成就行。如果你填的名字已经有解析，dun 会先问你要不要覆盖；覆盖前会备份，卸载时还原。

### 4. 装 Argo 隧道（菜单 6）

Argo 的流量走向：客户端连 CF 的 IP，CF 经过隧道把流量送到 VPS 上的 cloudflared。VPS 是主动连出去的，所以不用开任何公网端口。

安装时：

1. **选隧道**：如果你的 CF 账号里已经有隧道，dun 会问用哪条：
   - **新建一条**（推荐）：dun 自己建隧道、写路由、建解析，不用进 CF 后台。
   - **复用已有的**：只有这条隧道的 cloudflared 就跑在这台 VPS 上时才能选。dun 只往里加两条路由，原有的路由不动，也不另跑 cloudflared。那个 cloudflared 停了，Argo 节点也会断。
2. **选子域名**：只能是一级子域名（`xxx.你的域名`），dun 只会给这种。
3. **等它检查**：装完 dun 会从外面实际打开一次 Argo 域名，确认 CF → 隧道 → 本机这一路是通的。

装 Argo 时 dun 还会：

- 对这个子域名调低安全级别、关浏览器完整性检查、不缓存。整个域名的其他网站不受影响。
- 整个域名的 HTTP/3 没开的话打开它，UDP 版节点要用。
- 发现开着 Bot Fight Mode 时**先问你**要不要关。它只能整个域名一起开关，开着可能把代理流量当成机器人拦掉。

如果你的 CF 账号不让用 API 建隧道，dun 会教你在 CF 后台手动建一条，把 token 粘回来。**一定要新建一条隧道**，别用正在给别的域名用的隧道。

### 5. 记下订阅地址

装完屏幕上会打出两个订阅地址：

- `…/sub`：给 v2rayN、Shadowrocket（小火箭）、NekoBox
- `…/clash`：给 Clash Verge、FlClash 这类 mihomo 内核的客户端，自带分流规则

装了 Argo 的话，订阅地址走 Argo 域名；没装就走 CF WS 的域名。这两种情况下，VPS 的 IP 被墙了，订阅照样能更新。

以后想再看一遍，输入 `dun links`。链接也存在 VPS 的 `/etc/dun/links.txt`。

**订阅地址里那段随机字符相当于密码。** 泄露了就到菜单 9 里重置订阅地址，旧地址立刻失效。

### 6. 云厂商的安全组

dun 只能处理 VPS 系统里面的防火墙。甲骨文、谷歌云、AWS 这类云厂商，还要在网页后台的安全组里单独放行端口：

- Reality、AnyTLS、CF WS 的端口放行 TCP。
- Hysteria2 的端口和跳跃端口段放行 UDP。
- Argo 隧道不用放行任何端口。

## 三、导入客户端

### 用哪个订阅

| 客户端 | 用哪个地址 |
|---|---|
| v2rayN、Shadowrocket | `…/sub` |
| Clash Verge Rev、FlClash | `…/clash` |
| NekoBox | `…/sub`，但用不了 Argo 节点 |

导入方法：在客户端里找「订阅」或「配置」，新建一个订阅，粘贴地址，再点更新。各客户端的按钮位置以它的界面为准。

### 客户端版本要求

- **Reality、CF WS**：基本所有客户端都能用。
- **AnyTLS**：要新版客户端。
- **Hysteria2**：用了 gecko 混淆，要 mihomo 1.19.34、sing-box 1.14 以上。
- **Argo（XHTTP）**：要 v2rayN（Xray 内核）、Shadowrocket 2.2.66 以上（UDP 版要 2.2.78 以上），或新版 mihomo 内核的 Clash Verge Rev / FlClash。NekoBox、sing-box 官方客户端这类 sing-box 内核的用不了。

### Argo 的两个版本

订阅里每个 Argo 地址都有两个节点：

- `…-Argo`：走 TCP（h2）。
- `…-Argo-UDP`：走 UDP（h3）。晚高峰运营商常对单条 TCP 连接限速，这时 UDP 版往往更稳。UDP 被限速时就用 TCP 版。

嫌节点太多，可以在菜单 9 里关掉 UDP 版。

### 优选地址

CF WS 和 Argo 的节点会带上一批优选地址。来源有四种，在菜单 9 里开关：

| 来源 | 默认 | 说明 |
|---|---|---|
| 东京优选 IP（内置） | 开 | 从上海电信实测过的东京 IP。Argo 用 8 个，晚高峰 20-40 MB/s；CF WS 只用其中 172.64.229.x 的 2 个，原因见表格下面 |
| wetest 三网优选 IP | 关 | 每 3 小时刷新。电信的那几个多半落在新加坡，走 Argo 延迟约 2 秒、只有 0.2 MB/s |
| 内置优选域名 | 关 | 实测大多落在新加坡、美西、欧洲 |
| 自选地址 | — | 你自己加的，一直生效 |

为什么 CF WS 的东京 IP 少：CF WS 用的是普通的橙云域名，CF 不让这种域名走 108.162.198.x、172.64.52.x 这两个段，会直接返回 403（错误 1034）；Argo 的隧道域名没有这个限制。你自己加自选 IP 时，如果某个 IP 上 CF WS 节点不通、Argo 节点能通，多半就是这个原因。

哪个机房最快要看运营商。内置东京 IP 是按上海电信测的；移动、联通或别的地区的线路，可能更适合打开 wetest，或者加自己测出来的 IP。

自己加 IP：在菜单 9「添加自选地址」里加，格式是 `地址[:端口][#备注]`，比如：

```
172.64.52.178#东京
104.16.1.1:2053#家里最快
```

加完在客户端里更新一下订阅就有了。

## 四、日常管理

输入 `dun` 打开菜单，最上面能看到各协议的状态。常用的也可以直接敲命令：

```bash
dun links       # 再看一遍订阅和链接
dun log         # 看日志
dun restart     # 重启服务
dun syncip      # 机器换了 IP，同步解析
dun rehost      # 换节点域名（证书一起换）
dun update      # 更新内核：sing-box，装了 Argo 还有 Xray、cloudflared
dun upgrade     # 更新 dun 自己
dun uninstall   # 全部卸载
```

### 机器换了 IP

输入 `dun syncip`，解析会改成新 IP。订阅自动跟着变，客户端更新一下订阅就行。Argo 隧道不受 IP 影响。

### 证书

不用管：

- Reality、AnyTLS、Hysteria2 用的证书，dun 每 12 小时检查一次，剩不到 30 天自动续。想手动续，输入 `dun renew`。
- CF WS 和 Argo 用的是 CF 自己的边缘证书，CF 自己续。

### 从原版 dun 换到本仓库

已经装了原作者版本的机器，`dun upgrade` 会去原作者的仓库拉新版本。在那台机器上用本教程的安装命令重新跑一次，就换成本仓库的版本了，状态和配置都保留。

### 卸载

- 只卸载一个协议：菜单 13。它的解析、CF 规则和隧道会一起清理。
- 全部卸载：`dun uninstall`。dun 加的解析、CF 规则、隧道、证书、sing-box、Xray、cloudflared 和它自己全部删掉，BBR 设置会保留。

复用已有隧道装的 Argo，卸载时只删 dun 加的两条路由，隧道本身留着。

## 五、连不上？按这个顺序查

1. **云厂商的安全组**有没有放行端口，见上面「云厂商的安全组」。
2. **解析还没生效**：CF WS、Argo 刚装好，要等一两分钟。
3. **客户端太老**：对照上面的「客户端版本要求」。
4. **看日志**：输入 `dun log`。
5. **Argo 节点不通**，看装完时那次检查的结果：
   - 530：隧道没连上。在菜单 6 里看隧道状态。
   - 502：隧道连上了，但到不了本机的 dun。复用别人的隧道时，多半是那个 cloudflared 跑在 Docker 里，访问不到本机的 127.0.0.1。
   - UDP 出不去的机器，在菜单 6 里把隧道协议切成 http2。

还不行的话，到本仓库提 issue，附上 `dun log` 的输出。**发之前把链接里的 UUID、密码和订阅地址里的随机字符打码。**
